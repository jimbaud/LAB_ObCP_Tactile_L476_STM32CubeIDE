Lire l’API du projet

Les commentaires placés dans les en-têtes décrivent les contrats d’appel. Les commentaires du fichier source expliquent ensuite l’algorithme. Les fonctions privées possèdent aussi leurs contrats et apparaissent dans les pages de fichier.

Commencer par Carte et ordonnancement, puis suivre les liens vers les pilotes et les modèles. Les pages de fonction proposent leur source et les appels associés.

Un paramètre marqué in est lu. out reçoit un résultat. in,out conserve un état entre deux appels et peut être modifié. Les unités et capacités de tampon sont précisées près de chaque paramètre.

Les structures relient les données à leur rôle. App possède les modèles, Renderer possède le tampon de bande et Storage fournit les callbacks du port physique. Les fonctions app_touch et app_render séparent la commande de l’interface de son dessin.

Générer les pages

Avec Doxygen et Graphviz installés, lancer depuis le dossier du projet 

doxygen Doxyfile

Ouvrir ensuite build/documentation/html/index.html. Les fichiers XML permettent de contrôler que les descriptions et paramètres sont présents. Le journal des avertissements est build/documentation_warnings.txt.

Le README GitHub et les guides du dossier docs présentent les mêmes parcours avec des explications progressives et des captures du moteur graphique.

Question Points d’entrée
Que se passe-t-il à chaque tour ? obcp_task puis les fonctions privées de board.c
Comment un toucher ouvre-t-il une page ? touch_read, touch_update, app_touch et app_open
Qui dessine un pixel ? app_render, renderer_task et gfx_pixel
Comment conserver le dessin ? paint_save, storage_save et obcp_flash_storage
Comment piloter les jeux ? accel_read, tilt_sample et tilt_project
Comment produire le son ? audio_fill puis pwm_audio_task
